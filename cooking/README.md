# Cooking

用于记录家庭厨房中已经成功的菜谱、可调整变量和后续实验。

## 目录规则

按主要食材分类，例如：

```text
cooking/
├── README.md
├── beef/
├── chicken/
├── duck/
├── rice/
├── pork/
├── seafood/
└── vegetables/
```

每道菜只使用一个 Markdown 文件：

```text
beef/牛肉_炸锅烧烤.md
beef/煎肋眼牛排.md
duck/盐水鸭.md
duck/鸭汤豆腐菠菜粥.md
```

文件名使用简短、可直接理解的中文名称；需要在同一文件中覆盖多个部位或变体时，可使用“食材_做法”的形式。不要为同一道菜创建 `v1`、`v2`、`final` 等重复文件；历史版本由 Git 保存。

## 菜谱文件结构

每份菜谱按以下顺序记录：

1. **状态与适用条件**：稳定、待验证或已停用；同时注明设备、肉量、部位、厚度或块大小。
2. **成品目标**：预期风味、熟度、表面状态和口感。
3. **原料**：全部使用明确重量或体积，不写“适量”“少许”。
4. **前处理与腌制**：记录切法、是否冷冻、是否焯水、腌制时间和加料顺序。
5. **烹饪流程**：记录温度、火力、时间、翻面时点和静置时间。
6. **关键判断点**：说明什么时候应倒汁、翻面、出锅，以及失败时通常会出现什么现象。
7. **可变变量**：列出允许调整的变量、预计影响和推荐范围。
8. **实验记录**：放在文件末尾，按时间顺序追加，不删除旧记录。

## 记录规范

- 重量优先使用 `g`，液体可使用 `g` 或 `ml`。
- 温度使用摄氏度 `°C`；设备只显示华氏度时可同时注明。
- 时间精确到秒或分钟。
- 肉类必须记录部位、重量、厚度或块大小。
- 冷冻肉必须记录是否冷冻、冷冻时长和解冻方式；未知则写“未记录”。
- 尽量一次只改变一个主要变量，方便判断因果。
- 尚未实际验证的参数必须标注“待验证”或“推定值”。
- 实验确认更优后，更新文件前半部分的当前推荐方案，同时在末尾保留实验过程。
- 调味料优先使用美国 Arizona 常见渠道可以买到、保存期长且可用于多道菜的品种。

## 状态定义

- **稳定**：至少有一次明确成功结果，可以直接复现；重复成功后提高可信度。
- **待验证**：流程已整理，但成品结果尚未记录或部分参数为推定值。
- **已停用**：已被更好的方案替代，仅保留用于解释历史实验。
